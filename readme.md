# 中大日影 · 校園避曬地圖

中央大學計算機專題第十二組。用臺灣日期、時間與校園建築輪廓，查看指定位置在當下與半小時後是否有日照，並比較最短與避曬步行路線。

## 開啟地圖

- **上台展示或離線使用**　解壓縮後，用 Chrome、Edge、Firefox 或 Safari 開啟根目錄的 `index.html`。地圖、程式和編譯好的 C++ 核心都在這一個檔案內。
- **執行 Python 串接原生 C++ 的課程版本**　使用 Python 3.10 以上和支援 C++17 的 g++ 或 clang++。在專案根目錄執行下面指令，然後開啟終端機顯示的本機網址。使用標準函式庫，第一次啟動會編譯 C++，之後沿用相同版本的本機快取。

```sh
python run.py
```

預設網址為 `http://127.0.0.1:8000`。Windows 也可以用 `py run.py`。連接埠被占用時可用 `python run.py --port 8080`，結束時按 Ctrl+C。

## 從我在的位置走到校內目的地

開啟後即為「步行導航」，日期時間預設為臺灣現在時間。直接在地圖點目前位置 A，再點目的地 B，或在終點欄輸入「總圖」並選「總圖書館」。也可以先選目的地、對調 A 和 B，或點「用裝置定位」允許瀏覽器提供起點。在校外或無法定位時，仍可手動點圖。

兩點選好後，深綠色實線標出所選路線。地圖上方顯示時間與距離，按「看走法」可查看沿路的方向、轉彎與距離。依每分鐘 75 公尺的固定步速，沿步道距離最短的路線即為預估最快。點「避曬步行」會切換地圖與走法，調整日期、時間或避曬偏好可立即重算。選擇建築時，導航會帶到附近步道。畫面不提供室內導航與即時 GPS 追蹤。

## 課堂展示範例

1. 切到「陰影地圖」，在地圖左上角選「總圖書館周邊」，將日期設為 **2026-11-21**、時間設為 **15:00**。預設查詢點在總圖書館西側步道，15:00 有日照，15:30 進入第二行政中心投下的陰影。
2. 點建築查詢高度，再按「＋30 分」或「播放」。地圖上的虛線圈半徑為 100 公尺。另有地球科學院、教學研究綜合大樓與松苑餐廳三個示範區。
3. 回到同日 15:00，開啟「步行導航」。可在地圖上先點起點 A、再點終點 B，或各自選擇地標。按「載入範例」可重現下表的工程一館附近至教學研究綜合大樓附近；避曬偏好選 **4 倍**。

| 同一出發時刻 | 總路長 | 日照距離 | 遮蔭距離 |
| --- | ---: | ---: | ---: |
| 最短路線 | 約 269 m | 約 247 m | 約 22 m |
| 避曬路線 | 約 312 m | 約 94 m | 約 218 m |

同一組端點在同日 09:00、偏好 4 倍時，避曬解也是 269 m 的路線。改為下午 15:00，12 m 建築的投影由上午約 20.4 m 變成約 26.9 m，方向也改變，較長的 312 m 路線具有較低避曬成本。提高偏好可能會讓路線變長。兩條路線也可能重合。所選路線以綠色實線標示，另一條路線分岔的路段以棕色虛線顯示。夜間使用最短步行距離，並顯示夜間狀態。

## 程式如何分工

| 程式 | 工作 |
| --- | --- |
| `read_geojson.py`、`shade/campus.py`（Python） | 沿用小組的公尺座標基準，整理 OSM 建築外框、中庭、高度來源和步行路網。共享的原始道路座標形成路口，平面圖上的立體交叉不會自動接通。 |
| `shade/solar_model.hpp`（C++） | 共用小組原有的 NOAA 太陽位置公式，輸出中央大學的幾何太陽高度角與自正北順時針的方位角。原本的 `solar_position_offline .cpp` 仍可單獨編譯並使用原本的選單或參數。 |
| `shade/engine.cpp`（C++） | 依 `H / tan(太陽高度角)` 向太陽反方向投影屋頂與外牆，保留凹形建築與中庭。輸出陰影多邊形，判定指定點，計算道路日照距離，再用優先佇列執行 Dijkstra。 |
| `shade/native.py`、`run.py`（Python） | 載入 C++ 動態函式庫，驗證臺灣日期時間，取得太陽角度、陰影形狀、點位和路線，透過本機網頁與 JSON API 顯示結果。 |
| `build.py`、`web/` | Python 將資料、互動介面和同一份 C++ 核心的 WebAssembly 版本整合成單檔網頁。瀏覽器負責呈現地圖、時間軸與操作。 |

## 資料與模型假設

- 小組原有的 `export.geojson` 來自 OpenStreetMap，快照時間為 2026-11-15。當中有 111 棟建築、132 條道路圖徵。4 棟可依樓層數乘 3.5 m 估高，其餘 107 棟使用專案預設的 12 m。目前沒有直接標註高度的建築。地圖會逐棟顯示來源。
- 有 `height` 時優先取用公尺值，其次檢查 `building:levels`。若小組另外取得建築高度，可依 OSM ID 在 `buildings.json` 更新 `height`，並把 `height_source` 設為 `manual` 記錄人工填值。
- 單點查詢限於所選示範區半徑 100 m，計算投影時納入整份校園快照，以涵蓋圈外建築的投影。路線比較使用整個校園圖資裡允許步行的室外道路。地標選單會選擇附近的道路節點，位置不代表建築實際出入口。自選 A、B 會精確投影到最近的可步行線段，並在投影處分割路段。任兩個點都可以分別設定、對調、重新選擇。若兩點落在同一條路上，會計入兩個路面位置之間的實際長度。離路面超過 100 m 時會要求重新選點。點位至路面的虛線僅作定位提示，不計入路長。
- 路線固定使用出發時刻的陰影，路段每隔不超過 2 m 取樣。權重為 **遮蔭距離 + α × 日照距離**。計算不納入樹蔭、天候、地形、騎樓與施工狀態。日出與日落附近，區域外物體對結果可能有較大影響。這份結果尚未做實地遮蔭量測。
- 裝飾底圖 `shade/land.json` 包含 OSM 的草地、林地、水體、水道及球場，保留原始 way ID。這些地物只作定位參考。原始資料由 © OpenStreetMap contributors 在 ODbL 1.0 下提供，衍生地理資料沿用 ODbL。 [OSM 授權](https://www.openstreetmap.org/copyright) · [底圖取樣範圍](https://api.openstreetmap.org/api/0.6/map?bbox=121.183,24.964,121.199,24.974) · [NOAA 日照計算說明](https://gml.noaa.gov/grad/solcalc/calcdetails.html)

## 更新與驗證

改網頁或資料後，執行 `python build.py` 重新產生 `index.html`。若修改 C++ 計算，先安裝 Zig，再重新建置 WebAssembly 和網頁。若使用已安裝的 Zig，可設定環境變數 `ZIG` 指向執行檔。

```sh
python -m pip install ziglang==0.14.1
python build.py --wasm
python -m unittest discover -s tests -v
```

原生版每次啟動會依照 C++ 原始碼辨識快取。瀏覽器離線版需要將更新後的 `shade/engine.wasm` 與 `index.html` 一起收入版本控制。以 PyEphem 4.2.1 關閉大氣折射，獨立核對 2026 年五個日期、各四個時刻，幾何高度角差小於 0.007°、方位角差小於 0.051°。這項對照檢查太陽位置；建築高度與實地陰影仍需現場驗證。

### 路線驗算

- 以 2026-11-21 的 1,440 個出發分鐘，對三組不同地標、以及一組落在兩段道路中間的自選點，檢查 5,760 組端點與時刻。工程一館至教學研究綜合大樓出現兩條不同避曬解，地球科學院至松苑餐廳出現五條。總圖書館至行政大樓這一天的最優路形相同，路段的日照距離仍會改變。
- 另用 GEOS 多邊形聯集獨立重建陰影，按相同取樣定義算道路權重，再用 SciPy 的 Bellman–Ford 獨立求最低成本。測試涵蓋 13 組端點、8 個時刻和 3 種偏好，共 312 組，其中 264 組可達的最低成本相符，48 組皆判定不連通。測試包含不同道路中段、同路段分數位置、交換起終點、重合點與夜間。
- 時間或偏好改變時，最佳路線有機會仍走同一條路。畫面會列出兩種路線的總長、日照距離、遮蔭比例以及目前偏好下的成本，方便檢查為什麼選這條路。

## 放回小組 GitHub

壓縮檔中的 `CSproject_pubilc/` 是完整可執行專案。`GitHub-upload/` 只含網站新增或修改的檔案。可以從小組 GitHub 的最新 main 建立新分支，選 **Add file → Upload files**，將 `GitHub-upload/` **裡面的檔案與資料夾**拖到專案根目錄，提交後建立 Pull Request。這樣組員可以檢查變更再合併。若用本地 Git，也可將這些檔案複製到新分支的工作目錄後照平常方式提交。

若小組要用 GitHub Pages 展示，將 `index.html` 放在所選發布分支的根目錄，於 **Settings → Pages** 選擇該分支與 `/(root)`。網站能直接使用內嵌的 C++ WebAssembly。

# 中央大學建築圖資讀取模組 (Map Loader)

這個模組負責將 OpenStreetMap 的 JSON 資料讀取進 C 語言以雙向鏈結串列儲存為資料庫，並提供查詢建築高度與座標的 FUNCTION，供後續陰影幾何與避曬地圖計算使用。

## 檔案說明
* `map_loader.c` / `map_loader.h`：讀取與查詢函式。
*  `read_geojson.py`/讀取建築物原始資料

* `cJSON.c` / `cJSON.h`：JSON 解析套件。
*  `buildings.json`/建築物所有資料
*  `export.geojson`/建築物原始資料
下列為https://overpass-turbo.eu/
中抓取資料的程式碼
```
[out:json][timeout:25];

// 1. 鎖定「國立中央大學」的校園範圍
area["name"="國立中央大學"]->.ncu;

// 2. 同時抓取校內的「道路」與「建築」
(
  way["highway"](area.ncu);
  way["building"](area.ncu);
  relation["building"](area.ncu);
);

// 3. 輸出結果與節點座標
out body;
>;
out skel qt;
```

## 使用方式

請在你的主程式引入標頭檔：
```c
#include "map_loader.h"
```
